# SANPIN-Schedule: Автоматизированное составление школьного расписания

Проект для автоматического составления расписания учебных занятий в школе
с учётом санитарно-гигиенических требований (СанПиН / СП) и шкалы трудности
учебных предметов.

Система должна:

- распределять уроки по дням недели и урокам;
- контролировать суточную нагрузку в баллах для каждого класса;
- учитывать «одногорбый» и «двугорбый» профиль недели (распределение нагрузки);
- следить за занятостью кабинетов и учителей;
- избегать перегрузки учащихся тяжёлыми предметами.

## Основная идея

Каждому предмету назначается "вес" (количество баллов трудности за один урок).
Сумма баллов всех уроков в день для конкретного класса не должна превышать
установленный лимит (например, 20 баллов).

Алгоритм подбирает комбинации уроков по дням и урокам так, чтобы:

- выполнялся недельный учебный план (кол-во уроков по каждому предмету);
- не нарушались лимиты по баллам и количеству уроков;
- тяжёлые предметы ставились в оптимальное время (2–3 урок);
- нагрузка по дням недели соответствовала профилю работоспособности
  (более нагруженные дни — вторник, среда, частично четверг).

Минимальные требования

Python 3.10+

Библиотеки:

pyyaml (для чтения YAML),

ortools (планировщик, CP-SAT) — для решения задачи (можно заменить на любой ILP/CP-SAT).


Пример установки (локально):

pip install pyyaml ortools


Как пользоваться (план)

Заполнить входные файлы в папке data/ под конкретную школу:

перечень предметов и их трудность (subjects.yaml);

список классов и их недельный учебный план (classes.yaml);

кабинеты и их вместимость (rooms.yaml);

учителя и их нагрузку (teachers.yaml);

лимиты и профиль нагрузки по дням (sanpin_limits.yaml).


Запустить генерацию расписания:

python -m src.cli generate --data-dir data/ --output timetable.csv


Полученное расписание открыть в Excel / Google Sheets и при необходимости
откорректировать вручную.

## 2. `docs/Описание_проекта.md`

```markdown
# Проект «SANPIN-Schedule: Автоматизированное составление школьного расписания»

## 1. Введение

Учебное расписание в школе должно соответствовать не только учебному плану,
но и санитарно-гигиеническим требованиям. На практике это означает, что:

- у каждого учебного предмета есть своя "трудность" (количество баллов за урок);
- суточная и недельная нагрузка учащихся ограничена;
- тяжёлые предметы нельзя ставить подряд и на последние уроки;
- распределение нагрузки по дням недели должно учитывать динамику
  работоспособности (более нагруженные дни — вторник и среда).

Ручное составление расписания с учётом всех этих факторов сложно и занимает
много времени. Цель данного проекта — показать, как можно формализовать
эти требования и использовать алгоритмы оптимизации для автоматического
формирования расписания.

## 2. Цель и задачи проекта

**Цель:** разработать прототип системы, которая автоматически формирует
школьное расписание, учитывая:

- нормативные ограничения по нагрузке (в баллах и часах);
- количество кабинетов и их вместимость;
- занятость учителей;
- одногорбый и двугорбый профиль недельной нагрузки.

**Основные задачи:**

1. Определить формат входных данных (классы, предметы, учителя, кабинеты,
   лимиты СанПиН) в машиночитаемом виде (YAML).
2. Сформулировать математическую модель задачи (переменные, ограничения,
   целевая функция).
3. Реализовать каркас решателя на Python с использованием библиотеки
   целочисленного программирования (например, OR-Tools).
4. Продемонстрировать работу системы на учебном примере (несколько классов).

## 3. Упрощения для учебного прототипа

В рамках школьного проекта вводятся следующие упрощения:

- рассматривается одна школа и одна смена;
- каникулы, сокращённые дни, внеурочная деятельность не учитываются;
- каждый урок длится одинаковое количество времени;
- для части предметов используется усреднённая трудность (баллы);
- профиль недельной нагрузки (какие дни более тяжёлые) задаётся
  простыми коэффициентами по дням недели.

Эти упрощения позволяют сфокусироваться на принципе работы системы
и показать идею автоматизации.

## 4. Постановка задачи (кратко)

Для каждого класса требуется:

- расставить уроки по дням недели и урокам (слотам);
- выполнить недельный учебный план по предметам;
- не превышать лимит баллов в день;
- выдержать ограничения по количеству уроков в день;
- избегать постановки тяжёлых предметов в неудачные слоты (последние уроки).

Дополнительно система должна:

- не допускать, чтобы один учитель вёл два урока одновременно;
- не допускать, чтобы два класса сидели в одном кабинете одновременно;
- проверять, что численность класса не превышает вместимость кабинета.

## 5. Математическая модель (очень кратко)

Вводятся бинарные переменные:

- \( x_{c,d,p,s} = 1 \), если в классе \(c\) в день \(d\) на уроке \(p\)
  стоит предмет \(s\), иначе 0.

Основные ограничения:

- в каждый слот для класса — не более одного предмета;
- суммарное количество слотов по предмету за неделю равно учебному плану;
- сумма баллов за день (по всем урокам) не превышает лимит;
- тяжёлые предметы не ставятся на запрещённые позиции;
- учитель и кабинет не могут быть задействованы одновременно в двух местах.

Целевая функция минимизирует:

- отклонение суточной нагрузки от целевых значений по дням недели;
- количество "окон" в расписании классов и учителей;
- нарушения "желательных" правил (например, тяжёлые предметы на 1-м уроке).

## 6. Ожидаемый результат

Результатом работы системы является таблица расписания (например, в формате CSV),
которую можно открыть в Excel или Google Sheets. В таблице будут указаны:

- класс;
- день недели;
- номер урока;
- предмет;
- кабинет;
- учитель.

Далее расписание может быть при необходимости откорректировано вручную
администрацией школы.

## 7. Возможные направления развития

- Уточнение шкалы трудности предметов в соответствии с действующими
  методическими рекомендациями.
- Добавление второй смены и разных вариантов начала уроков.
- Учёт внеурочной деятельности и дополнительных занятий.
- Веб-интерфейс для редактирования входных данных и просмотра расписания.

# SANPIN-Schedule  
Краткое описание для школы

## 1. Для кого этот проект

Этот прототип сделан для школьной администрации, завучей и учителей,
которые сталкиваются с задачей составления расписания:

- нужно соблюдать учебный план и санитарные нормы (СанПиН);
- нельзя перегружать детей тяжёлыми предметами;
- нужно учитывать нагрузку учителей.

Проект показывает, как школьное расписание можно формализовать
и частично автоматизировать с помощью Python.

---

## 2. Что делает система

Система:

1. Читает исходные данные из простых файлов формата YAML:
   - список предметов и их «трудность» в баллах;
   - список классов и их ступень (5, 6, 7…);
   - список кабинетов;
   - список учителей и их допустимую нагрузку;
   - СанПиН-лимиты: сколько уроков и баллов можно в день.

2. Генерирует недельное расписание для нескольких классов так, чтобы:
   - выполнить учебный план (нужное количество уроков каждого предмета);
   - не превышать лимиты по урокам и баллам в день для каждой ступени;
   - более «тяжёлые» предметы попадали на «рабочие» дни (вторник, среда),
     а понедельник и пятница были легче.

3. Формирует удобные отчёты:
   - технический файл `timetable.csv` — для Excel/Google Sheets;
   - человекочитаемый `timetable.md` — таблицы по классам и дням;
   - отчёт по нагрузке учителей;
   - отчёт по нагрузке классов по СанПиН.

---

## 3. Какие нормы и ограничения учитываются

### 3.1. СанПиН и «баллы трудности»

Для каждого предмета задаётся трудность в баллах:

- например, математика — 4 балла,
- иностранный язык — 3 балла,
- история — 3 балла,
- более лёгкие предметы — 1–2 балла.

Для каждой ступени (5 класс, 6 класс и т.д.) в файле
`data/sanpin_limits.yaml` задаётся:

- максимальное количество уроков в день;
- максимальное количество баллов в день;
- недельный профиль нагрузки (какие дни могут быть более «нагруженными»).

Система стремится не выходить за эти лимиты.

### 3.2. Учителя

В файле `data/teachers.yaml` для каждого учителя указано:

- какие предметы он ведёт;
- максимальное число уроков в день;
- максимальное число уроков в неделю.

При построении расписания система старается:

- не ставить учителя в два класса одновременно;
- не превышать его дневные и недельные лимиты.

### 3.3. Классы и кабинеты

В данных есть:

- список классов (`data/classes.yaml`) c числом учеников;
- список кабинетов (`data/rooms.yaml`) с вместимостью.

В текущем прототипе кабинеты используются ограниченно,
но структура данных уже готова для того, чтобы учитывать
вместимость и профиль кабинета (физика, биология, спортзал).

## 4. Как этим пользоваться (на уровне школы)

### 4.1. Что нужно установить

Проект рассчитан на запуск в стандартной среде Python (например, на сервере школы
или на рабочем компьютере завуча).

Основные шаги:

1. Установить Python 3.10+.
2. Установить зависимости:

   ```bash
   pip install -r requirements.txt


3. При необходимости — зависимости для разработки и тестов:

pip install -r requirements-dev.txt

-------------------------------------------------------------

**4.2.** **Сгенерировать расписание**

**Базовый сценарий работы:**

Завуч или ответственный специалист заполняет файлы в папке data/ под свою школу:

предметы и их трудность;

классы и параллели;

учителя и их ставки;

СанПиН-лимиты.


Запускает скрипт генерации и экспорта:

python scripts/export_timetable.py


В корневой папке проекта появляются файлы:

timetable.csv — можно открыть в Excel/Google Sheets;

timetable.md — можно просмотреть на GitHub или распечатать.


**4.3.** **Посмотреть отчёты**

Для анализа нагрузки есть два дополнительных скрипта:

Отчёт по учителям:

python scripts/teacher_load_report.py

Показывает, у какого учителя сколько уроков в неделю и по дням,
и где есть перегрузка относительно заданных лимитов.


Отчёт по классам (СанПиН):

python scripts/class_load_report.py

Показывает, сколько баллов в день набирает каждый класс и
не превышен ли дневной СанПиН-лимит.


**5.** **Вариант работы через веб-интерфейс**

В проект встроен минимальный HTTP-сервис (FastAPI), который позволяет
получать расписание по сети — это шаг в сторону «школьного сервера».

**Запуск сервера**

uvicorn api.app:app --reload


Далее можно открыть в браузере:

http://127.0.0.1:8000/health — проверка, что сервис работает;

http://127.0.0.1:8000/generate-timetable — просмотр расписания в JSON-виде.

На основе этого API можно в дальнейшем сделать отдельный
веб-интерфейс для школы (простую администрацию расписания).



**6.** **Что можно развивать дальше**

Проект задуман как прототип, который можно расширять:

добавить строгий оптимизационный решатель (CP-SAT/ILP);

полноценно учитывать кабинеты и вместимость;

добавить поддержку второй смены и внеурочной деятельности;

сделать полноценный веб-интерфейс для редактирования данных и визуализации.

Но уже в текущем виде система показывает:

как формализовать требования СанПиН,

как автоматически получать расписание,

как проверять нагрузку по классам и учителям.
